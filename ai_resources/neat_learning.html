🤖 Step 1: Robots & Fitness (Score)

NEAT makes a bunch of “robot players” (AI agents). Each robot plays the same level one at a time. The robot earns a fitness score (like points). High score = better robot! 🏆

⚙️ Config Snippet

[NEAT]
pop_size = 200 # robots per generation
fitness_threshold = 600 # stop when reached
fitness_criterion = max # higher is better

You’re simulating: robots play → scores saved → best survive → babies created 🔄

🧬 Step 3: Mutation (How Robots Change)

After one generation, NEAT keeps the better robots and makes new robots by copying them… then adds small random changes called mutations. That’s how robots “evolve.”

⚙️ Config Snippet

[DefaultGenome]
weight_mutate_rate = 0.55
node_add_prob = 0.20
conn_add_prob = 0.20

Tip: If mutation is too low, robots don’t change much. If too high, robots become random.

4) Species & Stagnation (Teams and “No Improvement”)

NEAT splits robots into species (teams of similar brains) so one strategy doesn’t dominate too early. If a species stops improving, NEAT can remove it (stagnation).

Config Snippet

[DefaultSpeciesSet]
compatibility_threshold = 1.485
[DefaultStagnation]
max_stagnation = 5
species_elitism = 2

• Lower compatibility threshold → more species (more teams)
• Higher threshold → fewer species (bigger teams)

Takeaway (What the config really is)

This file is the rulebook for evolving robot brains: how many robots, how scoring works, how robots mutate, and how diversity is kept. It does not draw the game or change physics—only the AI evolution rules.

Tip for the student: If the AI isn’t learning, the #1 thing to check is the fitness function and whether the game resets properly between robots.
